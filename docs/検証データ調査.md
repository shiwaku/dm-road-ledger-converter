# 道路台帳DMデータの入手先と検証状況

調査日：2026年8月11日

## 背景と結論

公開リポジトリの検証に使える道路台帳DMデータを調査した。誰でも同じ手順で入手でき、
変換結果を公開できるデータであることを条件とする。

- 道路台帳を**DMフォーマットのまま公開**している自治体は見つからない（公開形式はSFC・DXF・Shape・画像）
- 一方、**豊中市は国土交通省DMフォーマットで販売している**（1,500円/図郭）。これが道路台帳DMを正規に入手できる唯一の実用ルート
- DM形式の**無償公開データは地形図・都市計画基本図**にあり（新潟市・大阪市・静岡市）、レコード解析と文字コード処理の検証はこれで足りる

### 検証には1図郭で足りる

実際に購入した図郭57-08（市役所付近）の実測値は次のとおり。

| 要素 | 件数 | 分類コード |
|---|---|---|
| 線（E2） | 2,647 | 40種 |
| 方向（E6） | 1,473 | 28種 |
| 記号（E5） | 1,210 | 40種 |
| 面（E1） | 400 | 18種 |
| 注記（E7） | 95 | 11種 |

件数はGeoJSONのフィーチャ数（E6はペアごとに1件へ展開したあと）。分類コードは重複を除くと全体で105種。

注記95件・記号1,210件・分類コード105種が入っており、1図郭で検証目的を満たした。加えて、

- 注記の文字コード（SJIS／JIS 7bit）と実データ区分（二次元／三次元）は作成元で一律なので、1図郭で判定できる
- 分類コードは本ツールが解釈せず `Code` として素通しするため、約300項目の網羅は不要
- 図郭をまたぐ接合（図郭ごとの原点処理）は、隣接56図郭が揃っている新潟市の公開DMで無償検証できる
- 不足しても1,500円で追加購入でき、要領第7条により申込当日交付

### 公開可否の解釈

遵守事項は「そのまま複製して営利販売しない」のみで、変換した成果物の公開を明文で禁じてはいない。ただし安全側の運用として、

- **DM原本をリポジトリに同梱して配布するのは避ける**（「そのまま複製」の再配布に当たり得る）
- 変換後のGeoJSONやスクリーンショットの公開は、様式1の「複製の目的及び利用方法」に明記して承認（＝交付）を受けておく

[図郭割図PDF（1,530KB）](https://www.city.toyonaka.osaka.jp/machi/doro/daityou/digitalmap/a00118002002000.html)から図郭番号を選定する。

### 留意点

- 遵守事項は「そのまま複製して営利販売しない」ことなので、変換ツールの検証利用は問題ない。ただし**リポジトリへのデータ同梱や変換後GeoJSONの公開**は、「複製の目的及び利用方法」欄に明記して承認を得ておく
- 全域規模で購入する場合は、CD-R 373図郭分の提供形態（枚数・納期）と大量取得時の扱いを事前に確認する

## PSEA による SXF → DM 変換

公開されている道路台帳SFC（北九州市）をDMに変換して検証に使う方法。

- ツール：[公共測量成果検査支援ツール PSEA Ver4.4](https://www.gsi.go.jp/KOUKYOU/sokuryosidou41021.html)（国土地理院・フリーウェア）
- 同梱の LogicalTranslator（著作権：関西大学）が数値地形図（旧拡張DM）⇔ SXF Ver2.0/3.0/3.1 を相互変換
- 操作マニュアルの「データ変換対応一覧」で SXF →数値地形図（旧拡張DM形式）は ○

### 実行時の要点

- **32bit版を使う**。64bit版のZIPには変換DLL（`conv_sxfdm.dll` / `conv_dmsxf.dll` / `common_lib*.dll`）が含まれない。32bitバイナリなので64bit WindowsではWOW64で動作する。インストーラ不要
- 操作：`PSEA.exe` →［ファイル］→［LogicalTranslator による DM<==>SXF 変換］→ SXF→数値地形図

### 変換で失われるもの（実測）

北九州市 `265-25.SFC`（3.6MB）を変換した結果：

| 項目 | 結果 |
|---|---|
| 生成された要素 | E2 のみ 17,498件（**E1・E5・E7 は0件**） |
| 実データ区分 | 全て `3`（三次元） |
| 分類コード | **`9001`〜`9135` の連番**。図式コードは復元されない |
| 縮尺・図郭 | Mレコードから500を取得。図郭 X 93226〜93523（297m）／Y -24410〜-23989（421m）＝A1判1/500と整合 |

同梱の対応表 `@DmLayerNameList.txt` は標準図式408キャプションのみで9000番台を持たない。北九州市SFCのレイヤ名255種のうち標準図式と一致するのは103種（`大字・町・丁目界`→1106 等）だが、変換結果には反映されなかった。残り152種は道路台帳固有（`真幅道路` `道路区域線` `区画線（中央部）` `Ｕ字溝有蓋` `盲人誘導ブロック板` 等）。

### LogicalTranslator で変換した場合（`00000001.dm` ＋ `Index.DMI`）

同じSFCをLogicalTranslatorで変換すると、上記のエクスポートとは別の結果になる。

| 項目 | 結果 |
|---|---|
| 要素 | E3（円）3,420／E7（注記）1,057／E2（線）614／E4（円弧）433。**E1・E5 は0件** |
| 実データ区分 | 全て `2`（二次元） |
| **座標** | **全て `9999999` / `-9999999` に飽和して無効** |
| 図郭座標 | 0（Mレコードの図郭座標レコードが全て0） |
| 分類コード | E2・E3・E4 は `0000`、E7 は `8100`（注記）のみ |
| 注記文字列 | **空**。1,057件すべて同一内容で、文字列フィールドに文字が入っていない |

座標が壊れる原因はマニュアルに明記されている仕様上の制約。北九州市のSFCは測量座標をmm単位で保持しており（例：`sfig_locate_feature` が `-24309509` / `93252002` ＝8桁）、**数値地形図の座標値上限7桁を超えるため飽和する**。

### 結論

PSEAを経由するルートは、どちらの方法でも道路台帳DMの検証データにはならない。

| | PSEAエクスポート | LogicalTranslator |
|---|---|---|
| 座標 | 有効（図郭座標＋mmオフセット） | **無効**（7桁飽和） |
| 注記（E7） | 0件 | 1,057件だが**文字列が空** |
| 記号（E5） | 0件 | 0件 |
| 分類コード | `9001`〜`9135` の連番 | 全て `0000` |
| 実データ区分 | 3（三次元） | 2（二次元） |

線・面の形状とレコード構造の検証には前者が使えるが（実際にこれで三次元DMのバグを発見した）、注記・記号・分類コードの検証はどちらでも不可能。**豊中市データの購入が必要。**

## 実施済みの検証

### 注記デコード監査

全E7注記について、旧実装（cp932素通し）と新実装を全件比較した。

| データ | 注記件数 | JISとして復号 | 旧実装との差分 |
|---|---|---|---|
| 静岡市 都市計画基本図DM | 63,919 | 0 | 0 |
| 焼津市 国際航業DM | 12,866 | 0 | 0 |
| **新潟市 地形図DM（56ファイル）** | 16,893 | **321** | 321 |

新潟市データでJIS X 0208(7bit)の注記が実在した（`KL3w8674`→`北蒲原郡`、`Gr?7@~`→`白新線`、`#J#R`→`ＪＲ`、`!J29!K`→`（温）`）。余白が全角スペース(0x21)で埋められているため、記号ベースの推測を外した厳格判定でも検出できる。

データによっては、cp932に定義のないバイト列 `0x87A2` を含む注記がある（幅員の数値の文字間に区切りバイトが挿入されたもの）。未対応のまま。

### 三次元DM（実データ区分3）未対応バグ

PSEA変換した北九州市の道路台帳DMで発見。三次元DMは1点が X,Y,Z の21バイト（1レコード4点）だが、パーサは二次元の14バイト固定（1レコード6点）だったため、各要素の2点目以降でZ値と隣の座標が混ざっていた。

```
修正前: (124.834,161.239) (0.2,121.248) (162.899,0.2) (118.743,163.998) (0.2,116.522)
修正後: (124.834,161.239) (121.248,162.899) (118.743,163.998) (116.522,164.893) (113.079,166.038)
```

修正後、座標が図郭内に収まった（X範囲250.4m・Y範囲400.2m ⊂ 図郭297m×421m。修正前はX範囲410.3mで図郭を113m超過）。面4,138＋線13,360を認識。

影響範囲：

| データ | E1/E2の実データ区分 | 影響 |
|---|---|---|
| 新潟市 地形図DM | 二次元 437,495 ／ **三次元 2,753**（10ファイル） | 修正前は座標が破綻。1要素の例で頂点の89.4%がずれていた |
| 静岡市 都市計画基本図DM | 二次元のみ | 影響なし |

## 検証用に購入する図郭の選定

[図郭割図PDF](https://www.city.toyonaka.osaka.jp/machi/doro/daityou/digitalmap/a00118002002000.files/500zukakuwari.pdf) を解析し、各マスの地物描画密度（マス内の描画ピクセル比）を測定した。中央値は5.0%。

図郭割図の凡例に次の記載がある。

> 隣接の図郭とセットで1図郭とみなしている図郭があります。これらは1図郭分の費用で、複数の図郭をお求めになれます。

赤枠を判定した結果、**複数マスを1セットとしている箇所が59あり**、最大4マスのセットが3組ある。同じ1,500円でマス数が増えるため、セットを選ぶのが有利。

### セット図郭は内容量では不利

セットを構成するマスは市域の縁にあり、大半が市外＝白紙である。1マスあたりの密度を測ると中央値5.01%の半分以下しかない。

| セット | 内訳 | 平均 |
|---|---|---|
| 67-66 ほか4マス | 67-66:4.9%／67-76:4.6%／67-85:0.0%／67-86:1.7% | 2.8% |
| 48-54 ほか4マス | 48-54:7.2%／48-55:0.0%／48-64:2.7%／48-65:0.0% | 2.5% |
| 47-51 ほか3マス | 47-42:1.9%／47-51:0.3%／47-52:4.4% | 2.2% |

「1図郭分の費用で4マス」は、内容が少ないマスをまとめて普通の1マス弱にしているという意味であり、データ量目的でセットを狙う意味はない。

### 候補（単独マス・密度上位）

| 図郭 | 密度 | 位置の性格 |
|---|---|---|
| 38-65 | 9.86% | 北部（千里方面） |
| 48-91 | 9.67% | 中部東側 |
| 67-59 | 9.12% | 南部の密集市街地 |
