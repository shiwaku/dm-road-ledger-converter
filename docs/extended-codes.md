# 拡張コード（自治体独自コード）

道路台帳図には公共測量標準図式に無い自治体・測量ベンダー固有の分類コードが混ざります。**豊中サンプル（図郭57-08）では105コード中28コード・860件（14.8%）がこれにあたります。** 混ざること自体は道路台帳図では普通のことで異常ではありませんが、どれが固有コードかを知らないまま扱うと表示が静かに劣化するため、変換のたびに一覧します。

- [点検する](#点検する)
- [提供元を指定する](#提供元を指定する)
- [既存アイコンで代替する](#既存アイコンで代替する)
- [「名称が無い」と「標準図式に無い」は別の話](#名称が無いと標準図式に無いは別の話)

## 点検する

```bash
npm run check:extended         # 変換結果を点検する
npm run check:extended -- --json
```

`scripts/build.sh` は DM→GeoJSON の直後にこれを実行します（`SKIP_CHECK=1` で飛ばせます）。

```
■ 拡張コード（標準図式に無い）: 28 コード / 860 件（14.8%）
   コード  件数    地物          アイコン
   2229     133  線・面        （アイコンを使わない地物）
   4143     119  記号・方向    dm-4231（toyonaka の代替表）
   4145     100  記号・方向    dm-toyonaka-4145（toyonaka の区画）
   4191      82  記号          dm-4161（toyonaka の代替表）
   2245       5  方向          dm-ext1-2245（ext1 の区画）
   8132       3  記号・注記    ―（代替図形の丸）
```

判定の根拠は dm-sprite の [`data/standard-codes.csv`](https://github.com/shiwaku/dm-sprite/blob/main/data/standard-codes.csv)（453コード）です。標準か拡張かの機械判定のために起こされた表で、これだけが完全です。`viewer/src/dmCodes.ts`（435件）や dm-sprite の `data/symbols.csv`（372件）は欠けがあるため判定には使いません。ネットワークが使えない場合は隣に置いた `../dm-sprite` のクローンを見にいきます（`--codes=<path>` で差し替えもできます）。

終了コードは、**拡張DMのアイコンを持っているのに提供元を指定していない場合だけ** 1 になります。

```
!! 提供元の指定漏れ: 2 コード / 87 件
   2245（5件）→ ext1
   4191（82件）→ toyonaka
```

この状態はエラーにならないまま代替図形の丸に落ちるため、見た目からは気づけません（実際 `dm-2245` の改名で豊中サンプルの5件が黙って丸になっていたことがあります）。逆に、**別の自治体のデータで指定しないのは正しい判断**です。拡張DMコードの意匠は提供元ごとに違うため、当てるべきでない意匠を当ててしまいます。

ビルドはこの検出では止まりません。タイル自体には影響せず、ビューワの表示だけの問題だからです。最後にもう一度警告を出します。

## 提供元を指定する

dm-sprite はアイコンを2種類に分けて配っています（[dm-sprite#23](https://github.com/shiwaku/dm-sprite/issues/23)）。

```
dm-4132            標準図式。全国共通なので区画なし
dm-ext1-2245       拡張DM。提供元が未特定のもの
dm-ext1-9101100    同（分類コードが7桁のもの）
dm-toyonaka-4145   拡張DM。豊中市の運用（豊中市の区画）
```

**いま dm-sprite にある区画は `ext1`（6コード）と `toyonaka`（7コード。2026年8月15日の [dm-sprite#30](https://github.com/shiwaku/dm-sprite/pull/30) から）です。** 豊中市の区画には `4191` が入っていません（図面では標準の `4161` と同じ意匠なので、dm-sprite は「図面に無い区別は発明しない」方針で作らないと決めた）。そのため `4191` は[代替表](#既存アイコンで代替する)で `dm-4161` を指して解決しています。設定の `toyonaka` は、**区画と代替表の両方を引き当てるキー**として働きます。

もし将来 `dm-toyonaka-4191` が配信されれば、ビューワは**無修正でそちらへ切り替わります**（区画のアイコンは代替表より先に採るため）。切り替わったら代替表の `4191` の行は不要になるので外してください。`npm run check:extended` の出力が `dm-4161（toyonaka の代替表）` から `dm-toyonaka-4191（toyonaka の区画）` に変わるのが目印です。

拡張DMコードの意匠は提供元ごとに違うため、**表示するデータの提供元と一致していなければ他所の意匠を当ててしまいます。** どの提供元のPMTilesかはビューワからは判定できないので、既定は同梱の検証データ（豊中市サンプル）に合わせた `ext1,toyonaka` にしてあります。

```bash
# 別の自治体のDMを焼いて表示するとき（必ず上書きするか空にする）
VITE_DM_PROVIDERS= npm run dev
VITE_DM_PROVIDERS=yourcity npm run dev
```

カンマ区切りで、書いた順に優先します。同じコードに標準と拡張の両方がある場合は標準を優先します。挙げなかった提供元の拡張DMコードはアイコンを引けず代替図形の丸で描かれます。位置は出るので地物が消えることはありません。

## 既存アイコンで代替する

dm-sprite は「どんなアイコンが存在するか」だけを持ち、**どのコードをどのアイコンで代替するかは、そのデータを扱う側の判断**という切り分けになっています（[dm-sprite#22](https://github.com/shiwaku/dm-sprite/issues/22)）。図面から起こした意匠が既存アイコンと同じなら、同じ絵を別のキーで二重に配らず、利用側が既存のキーを指します。

その対応表が `viewer/src/basemap.ts` の `ICON_ALIASES` です。**提供元ごとに持ちます。**

| 分類コード | 代替先 | 根拠 |
|---|---|---|
| `4191` | `dm-4161` マンホール（水道） | 図面では丸囲みの「水」（㊌）で、標準の `4161` と同一意匠。図面が両者を記号で描き分けていない（大きさは `4191` が `4161` の73%だが形は同じ） |
| `4143` | `dm-4231` タンク | 図面では素の円（外形0.540m）。`dm-3519` とも同形だが、外径18.88pxで 41xx の兄弟（`dm-toyonaka-4133` ほか＝18.62px）に大きさがそろう方を採った（`dm-3519` は22px） |
| `2224` | `dm-8199` 指示点 | 図面では塗りつぶした点（外形0.254m）。比率差0.0%・覆い率100/100で同形。実寸も6.16px相当で `dm-8199` の6.00pxと近い |
| `4146` | `dm-7303` 多角点等 | 図面では円の中心に点（外形0.413m）。dm-sprite の実測で覆い率97.0/89.3、目視で同一 |
| `4147` | `dm-7303` 多角点等 | `4146` と幾何が完全に同じ（外形・半径の峰・線分がすべて一致） |
| `4181` | `dm-2235` 雨水桝 | 図面では四角の枠（外形1.30〜1.43m）。覆い率100/89.6で形は同じ。**大きさは合いません**（`2235` は0.60m角）。合わせるなら dm-sprite に `dm-toyonaka-4181` を作ることになります |

代替先がスプライトに無い場合は警告を出して無視します（存在しないアイコンを要求して地物を消さないため）。追加するときは図面での確認と出典を必ず書き残してください。

`4191` の行は**豊中市の区画（`dm-toyonaka-4191`）が配信されるまでの措置**です。区画のアイコンは代替表より先に採るため、配信されればビューワは無修正で切り替わります。切り替わったらこの行は外してください。

## 「名称が無い」と「標準図式に無い」は別の話

ビューワのポップアップは分類コードに公共測量標準図式の名称を併記します（`2235` → 雨水桝）。名称表に無いコード（28コード）と、標準図式そのものに無いコード（28コード）は**別の話**です。名称表は図式の写しなので豊中サンプルではたまたま一致しますが、根拠が違います。

| 見たいもの | コマンド | 根拠 |
|---|---|---|
| アイコンがあるのに名称が無いコード | `cd viewer && npm run check:codes` | `viewer/src/dmCodes.ts` と dm-sprite のスプライト |
| 標準図式に無いコード（拡張コード） | `npm run check:extended` | dm-sprite の `data/standard-codes.csv` |

**「標準図式にあるか」の判定に名称表を使ってはいけません。** 詳しくは[ビューワの「分類コードの名称」](../viewer/README.md#分類コードの名称)を参照してください。
