# 道路台帳図ビューワ

変換して生成した PMTiles を表示するWebビューワです。MapLibre GL JS + PMTiles の構成で、UI・機能は dm-converter の[都市計画基本図ビューワ](https://github.com/shiwaku/dm-converter/tree/main/viewer)に揃えています（レイヤー定義だけが道路台帳図向けです）。

**デモ**: https://shiwaku.github.io/dm-road-ledger-converter/

```bash
scripts/build.sh /path/to/dm_dir   # 先に PMTiles を生成しておく

cd viewer
npm install
npm run dev      # → http://localhost:5175/
```

`npm run dev` は `output/road_ledger.pmtiles` を `viewer/public/` へ複製してから起動します。Vite の dev サーバは `public/` 以下しか静的配信しないためです。ポートは [dm-converter](https://github.com/shiwaku/dm-converter) のビューワ（5174）と同時に立ち上げられるよう 5175 にしています。

## 機能

| 機能 | 内容 |
|---|---|
| レイヤー切替 | 線・面・記号・方向・注記の表示ON/OFF。全ON/全OFFボタンあり |
| 地図記号 | 記号（E5）・方向（E6）は分類コードをキーに [dm-sprite](https://github.com/shiwaku/dm-sprite) のアイコンで描画。方向は `Angle` 属性で回転 |
| 標高値 | 標高点は記号の右脇に、等高線は線に沿って `Elev` を数値表示（[標高値について](../docs/output-spec.md#標高値について)） |
| 不透明度 | レイヤーごとにスライダーで調整 |
| レイヤー説明 | 各レイヤーの `i` ボタンで説明を開閉 |
| 背景地図 | 淡色 / 標準（地理院 最適化ベクトルタイル）／ 写真（地理院 全国最新写真）／ 白図（無地）を右下で切替。既定は淡色 |
| テーマ | ライト／ダーク切替。初回はOSの設定に従い、以降は `localStorage` に保存。ダークでは線・文字色を明色へ入れ替える |
| ポップアップ | クリック地点の地物の属性を日本語見出しで表示。**分類コードには公共測量標準図式の名称を併記**（`2235` → 雨水桝）。重なっている地物は最大20件まで |
| 記号・文字の大きさ | **地上サイズ固定**（1:500の図面と同じ見え方）。ズーム1段ごとに画面ピクセルを倍にする。字高・線幅・アイコンの倍率はすべてPDF図面の実測値（字高は標高値0.99m、町丁目名2.25m、建物名1.50m など） |
| 方向・注記の回転 | `Angle`（東を0度とする反時計回り）の符号を反転して MapLibre の `icon-rotate` / `text-rotate`（時計回り）へ読み替えて描画 |
| 位置の共有 | 地図位置を URL の `#ズーム/緯度/経度` に反映。位置指定が無い初回のみタイルの範囲へ寄せる |
| レスポンシブ | 640px以下ではボトムシート化し、初期状態で畳んで地図を広く見せる |
| PWA | manifest とアイコンを同梱。ホーム画面に追加可能 |
| 診断 | `?debug` を付けるとHUDを表示（ズーム・描画地物数・スプライトのアイコン数・欠けているアイコン・WebGLコンテキスト消失回数・ログ） |

色は都市計画基本図ビューワと同じで、白図（黒線）が既定です。ダークテーマでは線・文字・縁取りを明色へ入れ替えます。面は塗りません（PDF図面が塗っていないため）。レイヤー自体は残してあり、クリックで面の属性を拾う当たり判定になっています。

## 線・面の線幅と破線

**分類コードごとの線幅と破線は、同梱のPDF図面（`DM-_57-08.pdf`、A0のベクタPDF、1:500）の実測に合わせています。** 基本図ビューワが持っている公共測量標準図式の20パターンは使っていません。道路台帳図の分類コードは自治体・測量ベンダーによって運用が異なり、全国共通の図式として確定していないため、図式の書物ではなく図面そのものを基準にしています。

測り方は `scripts/measure-pdf.py` です（[検証](../docs/verification.md#図面の描き方を実測する)）。

```bash
python3 scripts/measure-pdf.py lines
```

図面の線幅は 0.30 / 0.42 / 0.54 / 0.84 pt の4種類で、図式どおりに分かれていました。既定は最も多い 0.42pt です。

| 線幅 | 分類コード |
|---|---|
| 0.84pt | `3002` 堅ろう建物・`6141` 堅ろう塀 |
| 0.54pt | `7101` 等高線（計曲線）・`1106` 大字・町・丁目界 |
| 0.42pt（既定） | `2101` 道路縁・`3001` 普通建物 ほか |
| 0.30pt | `7102` 等高線（主曲線）・`4146`/`4148`/`4149`・`2273` |

破線は実線と空白の地上メートルで持ちます（`line-dasharray` は線幅の倍数なので、地上サイズ固定の線幅と組み合わせると破線も地上サイズ固定になります）。

| 実線 / 空白 | 分類コード |
|---|---|
| 2.52 / 0.58 m | `1106` 大字・町・丁目界 |
| 1.59 / 0.53 m | `2233` 側溝 L字溝 |
| 1.30 / 1.15 m | `6201` 区域界・`6302` 耕地界 |
| 1.06 / 0.53 m | `2106` 庭園路等・`2230` |
| 0.71 / 0.61 m | `2234` 側溝地下部・`5107` 水路地下部 |
| 0.53 / 0.26 m | `3003` 普通無壁舎 |
| 0.44 / 0.44 m | `4146`・`4148`・`4149` |
| 0.26 / 0.53 m | `2273` |
| 0.26 / 0.26 m | `3402` 屋門・`6301` 植生界 |

`line-dasharray` は分類コードで切り替えられない（データ駆動に対応しない）ため、破線はパターンごとに別レイヤーへ分けています。実線は1レイヤーにまとめ、線幅だけをコード別に変えています。

`6136` 生垣（169m）だけは再現していません。図面には下地の線が無く、植生の記号を並べて表現しているためです（被覆区間で測ると実線率0.12）。既定の実線で描いています。

## 分類コードの名称

ポップアップでは分類コードの直後に公共測量標準図式の名称を出します（`2235` → 雨水桝）。対応表 `src/dmCodes.ts` は [dm-converter の同名ファイル](https://github.com/shiwaku/dm-converter/blob/main/viewer/src/dmCodes.ts)の複製です。図式は共通なので、どちらかを直したらもう一方にも同じ修正を入れます。

豊中サンプル（図郭57-08）では105コード中77コード、フィーチャ数では5,825件中4,965件（85.2%）に名称が付きます。標準図式に無いコードは「（標準図式に記載なし）」と出します。名称が出ないこと自体が「自治体固有のコードだ」という情報になるため、コードは隠しません。

名称表とスプライトは別々に育つので、整合を確かめるスクリプトを用意しています。

```bash
cd viewer && npm run check:codes
```

アイコンがあるのに名称が無いコードを検出します（あると「アイコンは出るのに記載なしと表示される」中途半端な状態になります）。dm-sprite は随時更新されるため、アイコン数はドキュメントに書かずこれで数えます。

**落とすのは標準図式のコードだけです。** 拡張コードは図式に名称が無いため名称表に足しようがなく、アイコンが増えるたびに落ちて直しようのない指示を出すことになります（豊中市の区画が dm-sprite に入った時点で実際に8コードが該当しました）。標準か拡張かの判定は `scripts/standard-codes.mjs` を通し、拡張コードは「名称表の対象外」として別に並べます（[拡張コード](../docs/extended-codes.md#名称が無いと標準図式に無いは別の話)）。

## 記号・方向のアイコンと代替図形

記号・方向のアイコンは公共測量標準図式のコードと共通なので、[dm-sprite](https://github.com/shiwaku/dm-sprite) をそのまま使います（アイコン数は随時増えるため `npm run check:codes` で数えます）。ただし道路台帳図には図式に無い自治体固有のコードが混ざるため、**スプライトのアイコンが無いコードは丸で位置を示します**。

起動時にスプライトの索引（`sprite.json`）を読み、アイコンのあるコードとないコードを排他フィルタの2レイヤーに振り分けています。アイコンの無いコードをそのまま `icon-image` で要求すると、その地物は何も描かれず黙って消えるためです。索引が読めなかった場合は全コードを代替図形で描きます。

スプライトのキーは `dm-<コード>` だけではありません。拡張DMは提供元の区画が挟まります（`dm-toyonaka-4145`）。指定のしかたは[拡張コード](../docs/extended-codes.md#提供元を指定する)を参照してください。

**方向にも矢印を使いません。** 方向要素（E6）は「向きを持つ記号」であって流向ではないため矢印は誤読を招きます。加えて、代替図形に回る全コードをPDF図面から切り出して確かめたところ、`4181`（8件、回転した四角）と `4214`（7件、旗）を除くすべてが小さな丸か点でした（その `4181` は `dm-2235` を、`4214` は豊中市の区画を指すようになったので、いまは方向レイヤーに代替図形は出ません）。丸は図面の実測（0.25〜1.4m）に合わせて直径1m相当にし、地色（`ink.halo`）で抜きます（白固定にするとダークテーマで白丸として悪目立ちするため）。向きは失われますが、角度はポップアップの `Angle` で確認できます。

豊中市サンプル（図郭57-08）での内訳は次のとおりです。

| レイヤー | 既定（`ext1,toyonaka`） | `VITE_DM_PROVIDERS=` で空にした場合 |
|---|---|---|
| 記号 1,210件 | アイコン 1,209件 / 代替図形 1件（1コード） | アイコン 989件 / 代替図形 221件（11コード） |
| 方向 1,473件 | アイコン 1,473件 / 代替図形 なし | アイコン 1,227件 / 代替図形 246件（9コード） |

差は豊中市の区画7コード（`4145`・`4134`・`4133`・`4214`・`4144`・`2225`・`2248`）と `2245`（`ext1` の区画）、それに代替表の6コード（`4191`・`4143`・`2224`・`4146`・`4147`・`4181`）です。件数は dm-sprite が189コードを持つ時点のものなので、**書き換えるときは `npm run check:codes` で数え直してください。**

既定で代替図形になるのは記号レイヤーの `8132`（1件）だけです。`8132` は注記系（`81xx`）のコードで、本来は注記レイヤーに出るものが記号レイヤーに1件だけ現れます。

アイコンで描かれるのは `6331` 広葉樹林（358件）・`2235` 雨水桝（347件）・`3401` 門（306件）・`7312` 図化標高点（262件）・`4151` マンホール（175件）など、公共測量標準図式にあるコードです。**dm-sprite 側にアイコンを追加すれば、ビューワ側は無修正でアイコン描画に切り替わります**（`2235` 雨水桝はこの経路で代替図形からアイコンへ移りました）。

## 電柱の向きを示す短い線

電柱系の方向要素（E6）は1要素に複数のペアが入ります。豊中サンプルでは **107要素／305件**が該当し（`4132` 電話柱 33要素・`4143` 36・`4145` 26・`4133` 6・`4134` 5・`4142` 1）、**全要素でペアの起点座標が同一**で、違うのは角度だけです（架線・支線の向き）。ペアごとに同じアイコンを角度違いで重ね描きすると、`4145` の斜線入りの円が2〜7回重なって真っ黒の円盤になります（[Issue #35](https://github.com/shiwaku/dm-road-ledger-converter/issues/35)）。

PDF図面は、約0.54mの円を要素につき**1個**描き、ペアごとに円の縁（半径0.27m）から約0.5mの短い線を1本出しています（`4132-0022` は円1個＋線5本。向きはDMの角度と一致）。DMのペア長は全コード3.00mの定型値なので、線の長さはデータから取れず、図面の値を使います。

ビューワも同じ描き方にしています（`src/layers.ts` の `STUB_CODES`）。

- アイコンは `Seq == 1` のフィーチャにだけ描く（要素につき1個）
- 線はペアごとに中心から引き、記号アイコンを上に重ねて内側を隠す。こうすると「アイコンの縁から線が出ている」見え方になり、アイコンの大きさがコードごとに違っても破綻しない
- 線の先端は中心から **1.1m**。図面は 0.27+0.5＝0.77m ですが、電柱系のアイコンは `ICON_SCALE` 0.5 でも中心から 0.61m（`dm-4142` は 0.80m）あって図面の円の2倍以上大きく（[Issue #13](https://github.com/shiwaku/dm-road-ledger-converter/issues/13)）、0.77m ではアイコンの下に隠れます。アイコンの縁から図面と同じ 0.5m 出る長さにしてあり、#13 でアイコンが図面の大きさに近づいたら 0.77m へ戻します
- 線の画像はスプライトに置かず、起動時に canvas で作って `map.addImage` する。図面の描き方の話であって記号の意匠ではないので dm-sprite に足さない。テーマで線色が変わるため画像名にテーマを含め、`styleimagemissing` で要求されたときに作る

単一ペアの電柱も同じ描き方になります。円形のアイコンを回すだけでは向きが出ないためです。`Seq` の無いタイル（載せる前に焼いたもの）では全ペアにアイコンを描く従来の動きに戻るだけで、消えはしません。

## アイコンの大きさ

**アイコンには全コード一律で 0.5 倍を掛けています**（`ICON_SCALE`）。dm-sprite のアイコンは 64x64 のキャンバスですが実際に描かれている範囲は 6〜44px とばらつき、倍率1.0のままだと図面より大きく描かれていました。

```bash
python3 scripts/measure-pdf.py symbols
```

PDF図面の記号49コードを実測し、スプライトのインク寸法（アルファ>8 の外接矩形）と比べると、倍率1.0では図面の **1.8倍**（コード単位の中央値）／**2.2倍**（件数で重み付けした中央値）ありました。

| 分類コード | 件数 | 図面での大きさ | 倍率1.0での大きさ |
|---|---|---|---|
| `6331` 広葉樹林 | 358 | 0.91m | 1.35m |
| `3401` 門 | 306 | 0.65m | 0.98m |
| `4151` マンホール | 175 | 1.06m | 2.45m |
| `6214` | 101 | 1.08m | 2.94m |

分類コードごとの補正はしていません。ラスタのスプライトを引き伸ばすと輪郭がぼやけるためです（`3401` 門は3.0倍で明確にぼけていました）。コードごとの比率は 0.7〜6.1倍とばらついたままで、これは dm-sprite のインクの大きさが揃っていないことに由来します（[dm-sprite#15](https://github.com/shiwaku/dm-sprite/issues/15)、[Issue #13](https://github.com/shiwaku/dm-road-ledger-converter/issues/13)）。**dm-sprite が更新されたら測り直してください。**

記号と文字の大きさは**地上サイズ固定**です。紙図面は1:500固定なので地上サイズが不変で、画面ピクセル固定にすると拡大時に図面より小さくなります。`groundSize()` が指数2の補間でズーム1段ごとにピクセルを倍にします（**z19 で 1m ＝ 8.157px**。緯度34.78度・512pxタイル）。z19未満は端の値で頭打ちになります。

ダークテーマでもスプライトのアイコンの色はそのままです（アイコンはSDFではない画像のため MapLibre 側で色を変えられません）。基本図ビューワと同じ挙動です。

## 注記・方向の角度

DMの角度は「水平右（東）を0度とする反時計回り」です。MapLibre の `text-rotate` / `icon-rotate` は時計回りが正で、回転前の文字列・アイコンはどちらも右（東）向きなので、**符号を反転するだけ**で読み替えられます。

注記だけは、基本図ビューワと同じく角度が ±90 のときに 0 へ倒します。豊中市サンプルでは ±90 度の注記29件すべてが縦横フラグ=1（縦書き）で、角度 ±90 は「文字列を寝かせる」指示ではなく縦書きの表現でした。そのまま回すと、縦書きのはずの注記が横倒しの文字列として出ます。

本来の縦書き（文字を縦に積む）を出すには MapLibre の `text-writing-mode` が必要ですが、データ駆動にできず、そもそも縦横フラグがタイルに載っていない（`TILE_ATTRS` に `Vnflag` は無い）ため、横書きとして描いています（[Issue #4](https://github.com/shiwaku/dm-road-ledger-converter/issues/4)）。

注記・標高値の文字は地理院の最適化ベクトルタイルのグリフを借りて描いています。同グリフに含まれるフォントは `NotoSansJP-Regular` だけなので、`text-font` はこれを明示する必要があります。明示しないと MapLibre 既定の `Open Sans Regular` を要求して404になり、文字が黙って消えます。

## 帰属・承認番号の表示

測量成果の使用承認には「成果品の見やすいところに承認番号を明示すること」が条件として付きます。ビューワは右下の帰属コントロール（ⓘ）とパネル下部の脚注の2か所に、`VITE_DM_ATTRIBUTION` の文言をそのまま出します。**文言は承認書の指定どおりに書き、言い換えません**（[利用上の注意](../docs/legal.md)）。

どのPMTilesを表示しているかはビューワからは判定できないため、`VITE_DM_PROVIDERS` と同じく**既定は同梱の検証データ（豊中市サンプル）の承認番号**です。別のデータを焼いて表示するときは必ず上書きするか空にしてください。空にすると帰属コントロールと脚注からこの文言が消えます（他所の承認番号を出さないため）。

```bash
VITE_DM_ATTRIBUTION= npm run dev                                   # 文言を出さない
VITE_DM_ATTRIBUTION='測量法に基づく○○市長承認（使用）第○号' npm run dev   # 別の承認番号
```
